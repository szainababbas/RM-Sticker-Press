# Sticker Press

**Turn SVG artwork into native reMarkable ink** — strokes you can lasso, copy, resize, and
paste between notebooks, exported as a sideloadable `.rmdoc`. Runs entirely in your browser:
one HTML file, no install, no server, no account, works offline.

## Why native ink?

Most "templates" for reMarkable are PDFs — they render as a flat background you can't touch.
reMarkable's own image insert (firmware 3.27+) pastes raster pictures, but they pixelate when
scaled, dither on greyscale devices, and don't work in PDF-backed documents at all.

Native ink is different: it's the same v6 stroke format the tablet itself writes. Stickers made
with Sticker Press behave exactly like something you drew with the pen — crisp at any size,
erasable, lasso-able, and they work everywhere, including on top of PDF planners.

## Quick start

1. Download `index.html` (or open the hosted page) in a Chromium browser (Chrome / Edge / Brave).
2. Drop SVG files onto the page, or click **★ Add test star**.
3. Arrange, style (pen, thickness, colour, fills), then **Export .rmdoc**.
4. Import the file via the reMarkable desktop app (drag & drop), or the USB web interface on
   a reMarkable 2 (**→ Tablet** sends it there over USB). The Paper Pro has no web interface:
   with developer mode on, copy the `.rmdoc` over SSH instead (see below).
5. On the tablet: lasso a sticker, copy, paste into any notebook.

Pre-made test files are in [`samples/`](samples/) if you want to verify your device first.

## Features

- **PDF hybrid documents:** drop a PDF (e.g. a planner exported from Affinity/InDesign with
  working hyperlinks) and it becomes the page backgrounds; your stickers export as ink on
  top, in one .rmdoc. The ink-to-PDF coordinate mapping (226 DPI) was calibrated on a
  physical Paper Pro. This is the only way to put movable elements onto PDF pages —
  reMarkable's built-in image insert excludes PDFs entirely
- **Devices:** Paper Pro, Paper Pro Move, reMarkable 2, Paper Pure — correct page geometry for
  each, with automatic greyscale mapping on the mono devices
- **Fills:** outlines, directional/cross hatching, and a *solid fill* mode using the same
  stroke parameters found in commercial sticker packs (rows fuse into flat colour)
- **Colour:** per-element colour matched from your artwork to the reMarkable palette, or a
  single-colour override
- **Pens:** fineliner, ballpoint, marker, pencil, paintbrush, calligraphy, shader, highlighter
- Multi-page sheets, full-page import (one SVG per page), rotation, duplicate, undo/redo
- Optional **Writing layer**: artwork exports on a "Template" layer with an empty layer on top
  for your notes
- Autosave in the browser + project save/load as JSON
- Ink budget meter so pages stay snappy to sync and lasso

## Preparing artwork

Flatten text to curves and expand strokes before exporting your SVG (in Affinity:
Layer → Convert to Curves). `<text>`, `<use>`, masks, and clip paths are not converted;
gradients are quantised to the nearest flat palette colour.

## How it's validated

The `.rm` v6 binary writer was built from scratch and verified **byte-for-byte** against
[rmscene](https://github.com/ricklupton/rmscene), the reference implementation derived from
real device files. The test suite round-trips exports through rmscene's parser (zero unread
bytes across stress documents of 600 strokes / 24k points) and has been confirmed working on
a physical reMarkable Paper Pro. See [`tests/`](tests/) and [`DEVELOPMENT.md`](DEVELOPMENT.md).

## Limitations (honest list)

- Chromium-based browsers only (the SVG sampling leans on browser geometry APIs)
- Per-point pen dynamics are sensible constants, not recorded strokes — ink can feel uniform
- The solid-fill thickness (≈7) is beyond what the pen UI produces; editing such a stroke
  on-device behaves like a very fat fineliner
- "→ Tablet" is for the reMarkable 2 only: it needs the USB cable and *Settings → Storage →
  USB web interface*, and it can send but not confirm (browsers can't read the tablet's reply).
  The Paper Pro ships no web interface at all (checked on OS 3.28: no `webui` service, nothing
  on port 80), so the app refuses the send there and points you to SSH
- Tested on a Paper Pro on OS 3.28.0.169 (1 October 2026); the v6 format is unchanged since 3.27

## Sideloading over SSH (Paper Pro)

With developer mode on and your key in the tablet's `authorized_keys`:

```sh
unzip My_Sheet.rmdoc -d sheet
scp -r sheet/* root@10.11.99.1:/home/root/.local/share/remarkable/xochitl/
ssh root@10.11.99.1 'systemctl restart xochitl'
```

The document appears at the top level of My files.
- No PNG tracing — for raster images, use reMarkable's built-in image insert instead
